# DataSense AI — Final Delivery Report

**Date:** 2026-11-07
**Project:** DataSense AI — Universal AIoT Data Intelligence Platform
**Stack:** FastAPI + SQLite + scikit-learn backend, Next.js 15.5.29 / React 19 frontend
**Status:** Delivered and verified — 27 backend tests pass, all live smoke checks pass,
14/14 pages render in a production build with 0 console errors.

## Executive summary

DataSense AI is a working multi-page AIoT data intelligence platform. Five genuine
public datasets are pre-loaded with documented provenance and SHA-256 checksums;
profiling, quality scoring, analysis, model training, anomaly detection, historical
IoT replay, the decision engine, report generation and CSV/JSON export all run against
that real data. There is no mocked data path, no fixture API and no fabricated metric.

All claims below were produced by running the commands shown, against this build. The
raw outputs are reproduced in `docs/TESTING.md`, and the supporting scripts are in
`scripts/` and `frontend/scripts/`.

`scripts/verify_checksums.py` confirms all five documented SHA-256 checksums match the
database exactly. Raw downloads are kept unchanged under `data/raw/`; the app reads
Parquet copies under `data/processed/`.

Honesty notes carried in the UI and `docs/DATASETS.md`:

- AI4I 2020 is synthetic data generated by its authors from a milling-process model.
  It is not factory-collected telemetry and is labelled as such.
- WDBC outputs are research demonstrations, not medical diagnoses.
- Credit Card Fraud was obtained from OpenML because the Kaggle listing requires
  authentication; features V1–V28 are PCA-anonymised by the original authors.
- Household power is the historical replay source; the IoT monitor simulates a stream
  over historical readings and is not a live sensor feed.

## Defects found by verification and fixed

Fifteen defects were found and fixed during end-to-end testing; the full table is in
`docs/TESTING.md`. The most significant:

1. Cascade delete removed database rows but left orphaned models, findings, analyses,
   anomalies, reports **and files on disk**. Delete now removes the processed Parquet,
   every upload extension variant, model artifacts, anomaly label files and report
   files, and the pytest test asserts on-disk removal.
2. Deleting a model left its findings behind; a model delete route and cleanup were added.
3. Nested `<a>` inside `<a>` in `Button asChild` caused React hydration errors; `asChild`
   now clones the single child.
4. Replay `speed` changes were ignored and `stop` could report `running`; both fixed.
5. PDF report generation crashed on a `null` analysis entry.
6. Dataset-detail histograms rendered empty; wired to real histogram bins.
7. The Reprofile button did nothing; it now reloads profile, quality and preview.
8. The models page showed only two of three models and no confusion matrix.
9. The Decision Centre hid findings unless a dataset was picked.
10. The topbar, switcher and page body could name different datasets; `useResolvedDataset`
    now syncs `?dataset=` deep links into the shared context.
11. Reports history could not be attributed to a dataset; the list now includes dataset
    name, file size and file existence.
12. The upload E2E called `process.exit()` before cleanup and left a fixture CSV in
    `data/uploads/`; the fixture moved to the OS temp directory.
13. The upload E2E wrote its screenshot one directory above the project, leaving a
    stray `e2e-upload.png` outside the delivered tree; the path is now project-relative.

## How to run

```powershell
# 1. One-time setup: virtualenv, Python + Node dependencies, dataset import,
#    reference-model training, backend import check
.\scripts\setup.ps1

# 2. Start the backend (health-checked, up to 30 s wait)
.\scripts\start.ps1

# 3. Build and start the frontend in a second terminal
cd frontend
npm install
npm run build
npm run start

# 4. Open http://localhost:3000  (API docs: http://127.0.0.1:8000/docs)

# 5. Stop both services
cd ..
.\scripts\stop.ps1
```

Use the production build (`npm run build` + `npm run start`) for verification. The
development server (`npm run dev`, Turbopack) produced spurious hydration warnings in
this environment that do not occur in the production build.

## Known limitations

- No frontend unit/component tests. Routing, console health, dataset consistency,
  upload and cascade delete are covered by the Playwright audit and E2E script.
- No performance/load benchmarks and no security or penetration testing. The app is a
  local single-user demo with no auth, no payments and no multi-tenant surface by design.
- Feature "why" explanations use permutation importance, not SHAP; the UI labels them
  accordingly. Cluster labels are unsupervised and are never validated against ground truth.
- AI4I 2020 is synthetic (author-generated) data; WDBC results are not medical advice.
- The IoT monitor replays historical readings; it is not connected to live sensors.
- The delivered report history keeps only the newest PDF + JSON pair per dataset.

## Conclusion

DataSense AI is delivered as a working, verified source distribution: five genuine
public datasets totalling 2,379,992 rows, three trained reference models with real
metrics, anomaly detection, historical IoT replay, an evidence-backed decision engine,
report generation and export. The backend passes 27 automated tests plus a full live
API smoke run; the frontend production build renders 14/14 pages with zero console
errors and passes a real upload/cascade-delete E2E test.
